# مراحل ۶ و ۷ — Export / Import و بکاپ شخصی

## مسیر اندروید

دکمه «ذخیره بکاپ در Drive / Files» این کارها را انجام می‌دهد:

1. داده‌های Repository محلی را می‌خواند.
2. فایل واقعی هر تصویر مدیریت‌شده را به Base64 تبدیل و داخل نسخه ۲ بکاپ JSON
   قرار می‌دهد؛ در نتیجه فایل فقط شامل URI محلی و غیرقابل‌انتقال نیست.
3. JSON را در پوشه خصوصی `tradelog-backups` می‌سازد.
4. Share Sheet سیستم‌عامل را باز می‌کند تا کاربر Google Drive، Files یا مقصد
   شخصی دیگری را انتخاب کند.

دکمه «بازیابی از Drive / Files» با Document Picker سیستم‌عامل فایل JSON
انتخاب‌شده را به cache اپ کپی می‌کند، آن را اعتبارسنجی می‌کند، تصاویر embedded
را دوباره در `tradelog-charts` می‌سازد و سپس Repository محلی را به‌صورت
تراکنشی Restore می‌کند.

بکاپ‌های قدیمی نسخه ۱ هنوز پذیرفته می‌شوند، اما فقط بکاپ نسخه ۲ فایل واقعی
تصاویر را همراه خود دارد. اندازه هر فایل ورودی/خروجی به ۱۰۰ مگابایت محدود
شده است.

## تست round-trip

```bash
npm run test:backup
```

تست سرویس این توالی را با همان موتور بکاپ و فایل‌های واقعی در یک پوشه موقت
روی دیسک اجرا می‌کند:

`Export → Share adapter → پاک‌کردن داده جاری → انتخاب همان فایل → Restore`

در پایان، تنظیمات، ترید، متادیتای تصویر و بایت‌های خود تصویر با نسخه اولیه
مقایسه می‌شوند. Share Sheet و Google Drive واقعی فقط روی دستگاه قابل تست
هستند؛ چک نهایی گوشی:

1. یک ترید همراه تصویر بسازید.
2. «ذخیره بکاپ در Drive / Files» را بزنید و فایل را در Drive ذخیره کنید.
3. داده‌های اپ را Reset کنید.
4. «بازیابی از Drive / Files» را بزنید و همان فایل را از Drive انتخاب کنید.
5. ترید، تنظیمات و تصویر را بازبینی کنید.

# مرحله ۸ — فایل استاتیک app-config.json

تنظیمات عمومی اپ از `public/app-config.json` خوانده می‌شوند. این فایل شامل
کلیدهای زیر است:

- `telegram_support_username`
- `sponsor_banner`
- `ad_network_ids`
- `min_app_version`
- `force_update_message`

`appConfig.ts` مسیر نسبی `/app-config.json` را از همان origin و بدون credential
می‌خواند. پاسخ با همان محدودیت‌های URL، طول رشته و ساختار داده normalize
می‌شود. اگر فایل وجود نداشته باشد، پاسخ نامعتبر باشد یا شبکه خطا بدهد،
`environmentRuntimeAppConfig` به‌عنوان fallback استفاده می‌شود.

`npm run build:web` فایل را بدون تغییر در `dist/app-config.json` کپی می‌کند و
یک تست byte-for-byte این موضوع را بعد از هر build بررسی می‌کند. پس از deploy
می‌توان همین فایل را مستقیماً از File Manager هاست ویرایش کرد و نیازی به build
مجدد نیست. در صورت وجود cache در CDN یا هاست، بعد از ویرایش cache را purge
کنید.

این فایل عمومی است؛ بنابراین فقط مقادیر عمومی بنر، شبکه تبلیغاتی، نسخه و
پشتیبانی باید داخل آن قرار بگیرند و نباید هیچ رمز یا کلید خصوصی در آن ذخیره
شود. هیچ migration، Edge Function یا کلاینت دیتابیس ابری برای این مرحله وجود
ندارد.

کامپوننت بنر فقط وقتی نمایش داده می‌شود که بنر فعال باشد، هر دو URL معتبر
باشند و تصویر با موفقیت preload شود. بنر در Dashboard و Settings قرار دارد و
لینک مقصد را خارج از نمای فعلی اپ باز می‌کند. صفحه حریم خصوصی نیز از Settings
در دسترس است. اتصال واقعی AdSense/AdMob و consent عمداً به مرحله بعد موکول
شده‌اند.
