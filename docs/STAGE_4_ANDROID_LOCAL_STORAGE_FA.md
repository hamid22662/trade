# مرحله ۴ — ذخیره‌سازی محلی اندروید

در نسخه نیتیو اندروید، تمام اطلاعات ژورنال فقط داخل فضای خصوصی خود اپ
نگهداری می‌شود:

- جدول‌های تنظیمات، نمادها، استراتژی‌ها، چک‌لیست، معاملات، تصاویر و
  یادداشت‌های روزانه در `tradelog.db` با `expo-sqlite` ذخیره می‌شوند.
- متادیتای تصویر در SQLite است و فایل واقعی تصویر داخل پوشه
  `tradelog-charts` در document directory اپ کپی می‌شود.
- حذف عکس، حذف معامله و Reset کامل، فایل‌های مدیریت‌شده مرتبط را نیز پاک
  می‌کنند. URIهای بیرون از پوشه TradeLog هرگز توسط اپ حذف نمی‌شوند.
- ساخت معامله همراه تصاویر، بستن معامله همراه تصاویر، import و restore در
  تراکنش exclusive انجام می‌شوند تا خطای میانی دیتای نیمه‌کاره نسازد.
- SQLite با WAL و foreign keys باز می‌شود و migrationهای موجود قبل از seed
  اجرا می‌شوند. اگر initialization شکست بخورد، اجرای بعدی امکان retry دارد.

نسخه وب نیز به‌وسیله فایل‌های `.web.ts` از IndexedDB/Dexie استفاده می‌کند.
تنظیمات عمومی PWA از فایل استاتیک `/app-config.json` روی همان هاست خوانده
می‌شوند و هیچ کلاینت دیتابیس ابری در برنامه وجود ندارد.

## بررسی خودکار

```bash
npm ci
npm run check
npm run build:android-apk
```

`npm run check` شامل بررسی مرز local-first، TypeScript، تست ماندگاری IndexedDB
و build وب است. دستور دوم Gradle `assembleRelease` را اجرا می‌کند و وجود
manifest، DEX، JavaScript bundle، منابع، کتابخانه بومی و امضای APK نهایی را
بررسی می‌کند.

## تست دستی روی گوشی اندروید

1. اپ را نصب و یک ترید با تصویر ثبت کنید.
2. اپ را کامل ببندید و دوباره باز کنید؛ ترید و تصویر باید باقی باشند.
3. ترید را ببندید و تصویر خروج اضافه کنید؛ داشبورد و تحلیل را بررسی کنید.
4. یک تصویر را حذف کنید و بعد خود ترید را حذف کنید.
5. یک ترید جدید بسازید، اپ را restart کنید و سپس از Settings گزینه Reset را
   اجرا کنید؛ همه داده‌ها و تصاویر باید حذف شوند و داده‌های پیش‌فرض دوباره
   seed شوند.
6. با پاک‌کردن Data اپ یا uninstall، انتظار می‌رود اطلاعات محلی از بین برود.
   قابلیت بکاپ قابل‌حمل تصاویر باید در مرحله بکاپ/restore نهایی تکمیل و جداگانه
   تست شود.
